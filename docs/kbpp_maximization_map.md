## External Benchmark Route

The KBPP route can be applied to external benchmarks, but the unit must change from "answer row recovered" to "verified semantic decision recovered under budget."

- Software benchmarks: treat each passed hidden test, localized edit decision, API binding, exception behavior, or patch invariant as a verified decision. The KBPP-style model should not be scored only on patch text likelihood; it should be scored on verified behavior under a fixed parameter/tool budget. Candidate proof expansion maps to retrieving relevant code spans, API contracts, failing traces, and invariant checks before patch generation.
- ARC-style grid reasoning: treat object identity, transformation rule, color/shape binding, spatial relation, and final grid cell decisions as verified decisions. The KBPP route maps naturally to object binding, relation composition, proof expansion over candidate transformations, and constrained output materialization. Public ARC tasks should be used as evaluation only; training should use generated ARC-like curricula with held-out transformation families.
- General benchmark adapter: split every task into `query/context -> latent proof/binding state -> constrained answer/action -> verifier`. The model gets credit when the verifier passes, not when the text sounds plausible.
- Claim boundary: success on software or ARC-like benchmarks only counts as 100M-vs-7B evidence if the 7B baseline uses the same context, candidate/proof budget, verifier, and hidden split, and if all added retrieval/proof-expansion modules are counted or declared.

Immediate benchmark plan:

1. Build a small external harness with three tracks: software unit-test repair, ARC-like generated grid tasks, and naturalized KBPP tasks.
2. Convert each task into verified decision bits: tests passed, grid cells correct, object/rule bindings correct, and final answer correct.
3. Evaluate three modes separately: 100M direct, 100M plus counted proof expansion, and modern 7B baseline with the same context budget.
4. Accept only if the 100M route beats the 7B baseline on verifier-scored decisions, not just on format or retrieval.

## Anti-Levers

- `learned_key_hash_or_auxiliary_anchor_inside_tiny_embedding_path`: Do not spend neural parameters learning deterministic keys; keep filters outside the neural path or encode keys as stable explicit fields.
- `overcompressed_membership_cards`: Remove repeated boilerplate, but preserve entity, member, relation, count, and constraint anchors.
- `neural_answer_equivalence_contrast`: Stage593 broad contrast regressed global binding; Stage594 residual-only contrast gives only a one-to-two-row current-evaluator gain and does not beat the established Stage525 raw-density frontier. Stage608 repeats the warning on the role-token entity schema: broad entity answer contrast lowers exact/answer KBPP and raises hard-filter corrections. Stage609 shows that narrowing to entity answer misses still fails to repair entity context and still lowers global KBPP. Answer equivalence is better handled by deterministic filters/correction, target-schema changes, or a selector-first objective.
- `larger_model_on_saturated_curriculum`: Only scale parameters after hidden entropy and composition depth scale with them.

## Maximization Rules

- Maximize target entropy per token before maximizing model size. The 16k band wins raw KBPP because the curriculum is compact and high-entropy; 100M is meaningless on a saturated target.
- Preserve discriminative binding anchors. The negative results are not from too many words; they are from removing anchors needed to separate near neighbors.
- Spend parameters on shared transforms, not deterministic lookup structure. Learned hashes and anchor sidepaths use capacity on structure a verifier/filter can provide exactly.
- Treat exact-key hard filtering as an access-layer ceiling, not model intelligence. Stage595 reaches `1.0/1.0` and `1.4143899091423784` bits/param for Stage525/594 only because every query has exactly one exact-key candidate.
- Track reliability as a separate multiplier on KBPP. Stage525 has the raw density peak, but Stage508/548 is the reliable frontier.
- Use tiny rungs as geometry microscopes and large rungs only after entropy expansion. The current general pilot needs 25031.638097675186x more hidden bits for a 100M screen.

Knowledge compression framing: KBPP is not low perplexity on knowledge-shaped text. It is verified semantic decision recovery under a constrained budget. The budget may be parameters, tokens, compute, memory, or declared primitives. The stages now support a clean two-regime distinction: recoverable typed access proves what is recoverable when semantic access operators exist, while model-owned internalization proves the model learned those operators without eval-time bridge leakage. GPT-style pretraining is broad and useful but access-uneven; it spends capacity learning language, co-occurrence, style, facts, and implicit retrieval together. The KBPP route instead engineers and audits reusable semantic operators: entity binding, full source-target/proof-pair matching, slot matching, relation/value compatibility, and proof-edge compatibility. The central bottleneck is binding, not raw capacity.
